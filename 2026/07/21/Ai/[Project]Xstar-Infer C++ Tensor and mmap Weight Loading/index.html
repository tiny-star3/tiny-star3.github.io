C++ Tensor 与 mmap 权重加载

Phase 1: C++ Tensor 与 mmap 权重加载

基础设施(Tensor 类 + 加载): 先造一个 C++ 的 Tensor——带 dtype(bf16/f32)、shape、自己拥有的一块内存。再写 pybind11 绑定,让 Python 能把数组喂进 C++、再把结果拿回来。然后 mmap:把权重文件直接映射进内存,Tensor 指着它,零拷贝。这是 Phase 1 的”地基”。

内存型算子(不涉矩阵乘):

  • rmsnorm:最干净,先做。f32 归约,对齐 PyTorch 数值路径。
  • embedding:查表,从 mmap 的权重表里按 token id 取向量。
  • rope:旋转位置编码,cos/sin 缓存 + split-half 配对。

矩阵乘 + Linear: matmul 是核心。Phase 1 手写 naive 三重循环,Linear = matmul + bias。这是最慢但最该吃透的算子。

组装:

  • attention:mask + softmax(f32) + 加权求和(bf16) + repeat_kv(GQA)。
  • mlp:复用 Linear,SwiGLU(gate*sigmoid(gate)*value)。
  • block:两个残差子层组装。

整模型: C++ 组装 N 个 block + ln_final + lm_head,mmap 加载全部权重,端到端前向。验收用 generate 连贯性(深层 bf16 发散,和 Phase 0 一样不追求 bit-exact,追求连贯中文输出)。

M1 — Tensor 基建 + mmap

  1. RAII 包一切资源,析构绝不抛异常: fd、mmap 映射、buffer 都用类包,析构兜底释放。若对象在栈展开(另一个异常正传播)过程中被析构,再抛第二个异常 → std::terminate 直接挂,无恢复机会——所以 ~MMapFile 的 munmap 失败只能 log + swallow,不能 throw。写 RAII 类第一件事想”析构失败怎么办”。
  2. 清理路径的 close 不检验,只有业务路径的 close 才检验: 你已经在为别的原因抛异常,中途清理的 close 再失败只能吞掉(吞进守卫析构),不可能再抛第二个。unique_fd 把这个区分机械化:清理靠守卫 dtor best-effort 吞,业务靠 release() 取出 fd 后手动 close + 检验——手写三处 close 必漏一处(你空文件那条就漏了),守卫从结构上消灭它。
  3. move 必须传播所有权标志,不只搬指针: owns_data_ 跟着 data_ 一起搬,否则”把 view move 给 owned”会让接收方析构时 free 掉 mmap 区 → double-free。两条析构路径(owned free / view 不 free)行为不同,各写一个测试钉死:owned 的 to_numpy 拷贝独立,view 的 to_numpy 别名共享。
  4. 半构造泄漏是 RAII 最容易漏的: 构造里每拿一个资源,后面所有可能抛异常的路径都要保证已拿资源释放——否则对象没构造完、析构不调,前面拿的就漏了。MMapFile 里 fd + 映射两种资源,fstat/mmap/close 任一步抛异常都可能泄漏 fd 或映射,守卫包 fd + 成功路径手动管 close 才堵全。
  5. 按字节移动指针要转 const char*,void* 不能算术: static_cast<const char*>(mf.addr()) + offset 才是”地址前移 offset 字节”;若转 int*,加 1 跳 4 字节,语义全错。C++17 更纯的写法是 std::byte*。
  6. 越界校验用减法避加法,防整数溢出: (offset > size) || (nbytes > size - offset),且先判 offset > size 保证 size - offset 不下溢(无符号减下溢成超大值)。offset + nbytes > size 在两者都大时会加法溢出绕回小值,漏判越界。
  7. 一个只能取一个有效值的参数不该存在: make_weight_view 故意不收 device——mmap 产物天生是 CPU 地址,收了就是误导 API(调用方以为能选 GPU,深处却抛”CUDA not implemented”)。职责分离:mmap→CPU 视图、CPU→GPU 另算。设计诚实性比”啥都加个参数”有深度。
  8. 零拷贝用别名法证明,不比指针: 造视图读一次 → 原地改底层文件 → 同一视图再读,若反映新内容即零拷贝,若等于旧快照即被偷偷拷贝。比”两个地址相等”强——它证明的是”视图实时读 mmap 活页”,正是 serving 零拷贝的真实价值。且不暴露裸指针给 Python。
  9. MAP_SHARED 而非 MAP_PRIVATE:PROT_READ 下两者读行为一样,但 MAP_SHARED 让多进程映射同一文件共享物理页,serving 多 worker 加同模型省内存。这是 llama.cpp 源码实测选择(查过,非记忆)。
  10. 初始化列表 std::move 参数后,body 里绝不能再碰它: shape_(std::move(shape)) 后用 shape.size() 会拿到 0(被 move 空)→ strides 空 → numel 走成员(对)与走局部(错)不一致 → memcpy 写越界 → 堆损坏。用成员 shape_,不用被 move 的参数。ASan 定位。
  11. move 赋值要判自赋值 + 先释放既有资源 + 末尾必 return: 不判自赋值 → 先 release 自己(=关掉 other 的 fd)再偷 → 悬空;不先释放 → 旧资源泄漏;if (this != &other) 结构自赋值分支掉到末尾没 return → 非空函数 fall-off = UB(-Werror=return-type 编译期抓、UBSan 运行期抓)。改法:开头 if (this == &other) return *this; 早返回。
  12. 返回局部对象用按值返回 + RVO/move,不要返回引用: return Tensor& 但返回局部对象 → 悬挂引用 = UB。move-only 类型尤其——按值返回编译器做 RVO/nrvo 或 move,零拷贝交出所有权(make_unique 惯例)。
  13. -fsyntax-only 不可靠于流敏感问题: return-type 这类控制流问题它抓不到,要真实 -c 才行。怀疑一个点用多工具交叉坐实:-Wreturn-type / -Werror=return-type / UBSan 三个独立信号,不靠单一结论。
  14. 头文件要自洽,别依赖传递包含: weight_io.h 自己用 int64_t 就自己 #include <cstdint>,哪天传递链断了就崩。include 自己的依赖,不假设”反正 .cpp 会带上”。

M2 — 内存型算子

RMSNorm

  1. bit-exact 是诊断手段,不是 gate: 朴素 f32 累加 rms += xij*xij 跟 PyTorch CPU reduction 在 hidden=1024 差 ~1e-6(几个 ULP),是累加顺序差、可解释、不是 bug。但 allclose(1e-6) 当 gate 会把 1-ULP 顺序差藏过去、真 bug(1e-1)溜掉。落点:宽松 gate(max_diff<1e-4)兜真 bug + 打印 max_diff 看量级诊断。每跑一个 case 先看量级再下结论。
  2. “reduce 恒 f32”是同源对拍选择,不是”求精度”: 你 reduce 在 f32、输出 dtype 跟 x,不是因为想要更准,是因为参考那么做——“和 reference 不一样就是对拍 bug”。这条原则 rope(cache downcast 放哪层)、M3 matmul(累加精度)反复投影。
  3. eps 在 sqrt 内,不在外: rsqrt(mean+eps) 不是 1/sqrt(mean)+eps。前者防除零,后者 eps 在分母外几乎不起作用且改变数学。对拍时这点和参考必须对齐。
  4. rsqrt 用 1.0f/std::sqrt 而非 std::rsqrt: C++ 标准库无 std::rsqrt,但编译器会把 1.0f/sqrtf(x) 优化成 rsqrtss 硬件指令(带 Newton 迭代修精度)。这是”靠编译器、别自己造”的实例——你写最直白的式子,让优化器替你做指令选择。
  5. Method A(非模板+运行时分派) vs B(模板+显式实例化): 你为”将来扩 FP8”想用模板,最后选 A。带走 C++ 链接认知:模板定义在 .cpp 对其它 TU 不可见 → 链接错误;同 .cpp 内不需要显式实例化。fp8 的事留给真要扩时再决,现在运行时分派够用且免模板膨胀。
  6. 任意秩靠”内部展平 + flat 索引”: num_rows = numel/hidden,所有前导维拍平成 num_rows,flat[i*hidden+j] 索引。不去搞”rank-N 通用 reduce”,因为 last-axis reduce 在连续内存下就是个 2-D 循环。这条直接复用到了 rope、M3 linear 的 collapse 前导维。

Embedding

  1. id 是 INDEX 不是 VALUE → 不进 DType 体系: token id 是”查哪一行”的索引,不参与浮点运算,所以它不配拥有 DType,只有 weight 是 Tensor(DType 恒 float-only)。这一句体现你对”数值”和”索引”两种语义的区分。
  2. vocab/hidden 从 weight.shape 取,不单独传: 单一真值源——weight 是 (vocab, hidden),这俩值已经在那了,再传一份就是两个真值源,传错了你信哪个?跟 “positions 长度从 x 推”是同一条:驱动输出形状的信息(这里 ids_shape)必传,能从已有入参推出的(id 个数?不,ids 没形状)不传——注意 embedding 的 ids_shape 反而必传,因为 raw 指针没形状且它驱动输出形状。这跟 rope 形成对照。
  3. py::array_t<T, c_style> flag 语义: 默认 c_style|forcecast 会静默转换(有损也转);只传 c_style 覆盖掉 forcecast → 拒绝有损(float64→int64)、允许安全宽化(int32→int64)、非连续被拷成连续。这是 binding 层类型安全的硬细节,int32 id 测试就是这条结论的回归探针——哪天 pybind 行为变了,这个 case 会先挂。
  4. 越界 = throw(单卡),mask 延后到 TP: vLLM 用 MASK 不 throw(因为 vocab parallel,越界 id 要 clamp 而非报错)。你现在 throw 是”单设备”的诚实选择,不假装支持你还不做的多卡。设计诚实性——别为一个不存在的场景提前写复杂逻辑(TP 时再加 mask)。
  5. mmap 零拷贝别名穿过 op: 改底层文件后 op 立刻反映新内容,且用改后正向断言(cpp1 == 改后 reference)证,不只断言”变了”。torch.from_numpy 是零拷贝 view,原地改 numpy 则 torch view 同变,直接拿来当改后 reference。这是 M1 mmap 投资的变现,也是 weight tying 地基(lm_head 和 embed view 同一 offset 即 tied)。
  6. footgun:np.array_equal(grad_tensor, x) 静默返 False: 内部 asarray 碰 requires_grad tensor 抛 Can't call numpy() on Tensor that requires grad,被它自己的 try/except 吞掉直接返 False——“值完全相同”却判不相等。对拍一律 torch.equal/allclose(不看 grad 只比值)。这条踩一次就记住。
  7. char*/const char* 转换做字节指针算术(跟 M1 第5条同源): embedding 的 gather 用 memcpy(dst + i*row_bytes, src + ids[i]*row_bytes, row_bytes),字节偏移靠 char*。注意是 ids[i]*row_bytes 不是 i*row_bytes——顺序 id 下隐身,乱序 id 才暴露(rope 同款铁律)。

RoPE

  1. 越界分支要独立 case,不能挤一起互相冒名: 最初 [5,20,-1] 想一个 case 测高低两端,但 core 从前往后扫,20 在 -1 前先抛 → -1 分支没被覆盖——“绿的保护伞”:删 < 0 分支,case 照样 PASS(20 兜住)。落点:上界 [5,20,3]、下界 [5,8,-1] 各一个独立 case,删哪个哪个挂。pytest.raises(match=) 只看 message 不看哪个值触发,所以”独立”才是真覆盖。这条是测试设计硬通货。
  2. cache 恒 f32 + op 内部 downcast,不是 caller downcast: cache 恒 f32,op 内 static_cast<bfloat16>——对齐 rope.py:cache buffer 恒 f32,downcast 在 forward 内 .to(x.dtype)。好处:引擎一份 cache 到处用,调用点不用各 downcast。同源对拍的精度选择要看参考在哪层做 downcast。
  3. bf16 路径中间不 downcast → 不 bit-exact: bfloat16*bfloat16 走 operator float() upcast,整表达式 float 算,赋值回 bf16 才 RNE 一次;PyTorch CPU bf16 每步 downcast。你少两次中间 downcast → 比参考高几个 ULP → allclose(1e-2),不是 equal。f32 全 float IEEE754 确定 → bit-exact(实测 CPU 此处无 FMA 收缩)。精度路径逐 op 决策,依据是”跟参考同源”,不是”越准越好”——跟 rmsnorm “reduce 恒 f32” 是同家族不同决策(rope 无归约)。
  4. 单一真值源两面的对照: positions 长度从 x.shape()[-2] 推(不传长度参数,因为能从已有入参推出);对比 embedding 的 ids_shape 必传(因驱动输出形状)。规则一句话:驱动输出形状的信息必传;能从已有入参推出的不传。raw 指针不能自报长度是固有局限 → 长度校验放 binding(py::array_t 免费拿长度),core 只校验值越界。
  5. 乱序输入铁律(跟 embedding 乱序 id 同款): rope 测 positions=[3,0,7,1] 全错位,抓 p=i vs p=positions[i];arange 下 i==positions[i] 隐身 bug。凡是”用输入值当索引”的 op,乱序输入是必测 case——这条从 embedding(id)到 rope(positions)到将来 attention 都成立。
  6. split-half 配对不是 interleave: Qwen2 的 rotate_half 是前半/后半配对 (x_i, x_{i+d/2}),不是相邻配对 (x_2i, x_2i+1)。写错 f32 立刻挂(数值完全不同)→ f32 case 本身就是 split-half 的守卫。配 Qwen2/Llama 必须是 split-half;有些模型用 interleave,别混。
  7. py::array_t::data() 在空数组上返回有效指针,别加 null 检查: 空 positions(=seq_len=0)core 循环 0 次永不 deref,安全。加了 null 检查是没意义的防御代码——pybind11 也不给 null。别为不存在的危险加防御。

M3 — Matmul + Linear

  1. bf16 容差 rtol 主导 —— rtol=1e-2 ≈ 1.28 bf16 ULP(7-bit 尾数,1 ULP≈2⁻⁷≈0.78%),atol 兜底近 0 元素;f32 纯 atol=1e-4。matmul/linear bf16 统一这组,有物理依据不是经验值。
  2. gemm_kernel 延后到 M4 —— matmul/linear 的 f32/bf16 双循环只差 static_cast,是 gemm 动机,但三消费者齐了(matmul/linear/attention)再抽。抽早=接口猜错=返工。

Matmul

  1. 长累加链必 f32 —— K-length dot product 在 bf16 累加下 big-eats-small(K=896 远早于此),累加器恒 std::vector<float>。是”reduce/累加恒 f32”族的新成员(rmsnorm reduce、rope cache 之后)。
  2. i-k-j 顺序 + A 标量外提 —— A 的元素在 j 循环是常量,外提到 kk 循环;j 最内层让 B 和 result 都 stride-1 连续。这是 naive 三重循环里唯一值得讲的数据布局判断。
  3. 非 bit-exact,走 allclose —— 累加顺序/tiling 异于 PyTorch,f32 也只 allclose 不 equal。
  4. 2-D only 契约,batched 延后 —— 给 M4 attention 的 batched Q@Kᵀ 留张力,不在 matmul 提前猜 batched 接口。
  5. fake green:没进 CMake 也能 build pass —— 文件没编译但 build 不报错,要盯 build log 的 .cpp.o 行。

Linear

  1. own loop,不调 matmul —— matmul=activation@activation(无 bias、无转置)vs linear=activation@weight+bias(有转置),契约不同不互调。这是”第二个消费者出现前别抽象”的反面教材:硬让 linear 复用 matmul = 接口错配 = 4 个 bug。
  2. 转置靠索引,非内存转置 —— weight 存 (out,in),forward 用 W^T,转置由 weight_data[kk+j*k] 在累加循环里实现,不拷不转。代价:weight 访问 strided,result 连续。这是 nn.Linear (out,in) 存储约定的本质。
  3. leading 维 collapse 成 shared-B —— (...,in)→(num_rows,in),同一 weight 应用到每行。跟 rmsnorm 的 flattening 同构。
  4. k = shape().back() 非 shape()[1] —— rank-2 下两者相等 bug 隐身,rank-3 测试才暴露。同 embedding 乱序 id、rope 乱序 positions、matmul A 步长一族的”两维度碰巧相等 bug 隐身”铁律。
  5. bias 加在 f32 再 downcast —— acc += bias; out = bf16(acc),不是 out=bf16(acc); out+=bias。downcast 永远最后一步,”reduce/累加恒 f32”族一致性。
  6. linear_py = None↔nullptr 桥接 —— core 用 const Tensor* 可空,pybind11 无默认转换,需 wrapper:py::object 通吃 + is_none() 分支 + cast<Tensor&>() 拿引用取地址。形参活过 return 无悬空。规律:签名有 pybind11 默认转换不吃的类型(裸指针/可空/ndarray)就要 wrapper。

M4 — Softmax / Attention / Gemm / Mlp / Block

Softmax

  • 任意轴 reduce 的偏移 = 线性编号解多维坐标:N-D 张量沿 dim 轴有 numel/shape[dim] 条一维向量,起点由”i 解成非-dim 轴坐标乘 stride 求和”得到。dim 轴不参与 row_idx 的进制分解——若 dim 也 /=shape[i] 会污染后续轴坐标(dim=last 全错)。row_start 是任意轴 reduce 的通用 helper。
  • signed/unsigned 比较陷阱:size_t rank 与 int64_t dim 比较,usual arithmetic conversion 把 signed 转 unsigned,dim < -rank 变成 (uint64)dim < (uint64)(-rank),-rank 绕回巨大正数——合法 dim=0 被拒、非法 -1 溜过。校验整个反了。修法:比较前 static_cast<int64_t>(rank) 落回 signed 域。-Wsign-compare 会警告。
  • max-init 必须是 -∞ 不是 0:全负向量下 0 < 任何负数 恒 false → max 永不更新停在 0;大幅值全负([-1000,-1001])时 exp(x-0)=exp(-1000) 下溢成 0 → sum=0 → 0/0=NaN。正确 max 让最大元素指数恒为 0,exp(0)=1 永不下溢,sum≥1。这是 docstring 自己写的保证被 0-init 打破。
  • “绿的保护伞”三层,测试都要主动打破:全等向量(max-shift 全 0 藏 max/sum bug)→ 造元素不全等;randn(有正有负,max 被正数更新,藏 max-init bug)→ 造全负大幅值(< -88 越过 float exp 下溢线);只测一个 dim(row_start 在 dim=0/last/middle 行为不同)→ 三个都测。
  • 跨 op 契约:softmax 内部已 downcast,attention 别再 downcast。C++ softmax 把 f32 焊死内部 + downcast 是 op 内部最后一步,attention 调完拿到的已是目标 dtype,照抄 Python .to(bf16) 会 no-op 或报错。
  • 测试 oracle 用自己的 Python reference 不是 torch.softmax——验证”我的 C++ == 我的 Python 参考”,不是”== PyTorch”。

Mlp

  • gate/up 融合 + chunk 指针切片:一次 gate_up GEMM 出 (rows, 2intermediate) 连续,chunk(2,-1) 指针切片取两半(gate=前半 +i\*2i+j、up=后半 +j+intermediate),零拷贝但产出是行步长 2intermediate 的跨步子矩阵。act 写进新连续 buffer 才能喂 down linear(lda=intermediate)。三次 buffer 分配,工业 fused-MLP kernel 折成一次是 Phase 5。

  • gate/up 顺序探针:silu 线性区让顺序 bug 隐身:silu(x)=x·σ(x) 大正数下 σ→1 → silu(x)≈x → silu(8)·16≈silu(16)·8(交换律+线性区联合吃掉换序差异),gate=10,up=10 探针差 0.0000。正确构造:gate 压 silu 非线性区(|x|小)、up 拉线性区——gate=1,up=10 差 36.8%。同 gemm k≠n、attention -inf 落下三角一族的”打破绿的保护伞”。
  • even-half 校验是 load-bearing 因整数除法:奇数 gate_up out(如 5)→ 5/2=2,只要 down[1]=2 就溜过。gate_up[0]%2!=0 拦这个口子。同 head_dim 整数截断陷阱。
  • School B 哲学:oracle 测”正确性”不是测”契约分歧”:C++ 用 f32 中间域 silu(刻意更精),torch 默认 bf16 是 per-step downcast(3 次)≠ C++(1 次)。拿 torch bf16 当 oracle = 测”我的算法 vs 另一个算法”,差多少没意义。而 down GEMM 的近抵消归约会把这个分歧放大成重尾无界:act 级仅 ~2 ULP,但 6 个近抵消求和放大成输出 47% rel,任何固定 rtol 都挡不住足够多 seed(500 seed→0.087,2000 seed→0.236,无上界)。结论:bf16 parity 若参考和实现 downcast 路径不一致,放容差是赌 seed 非测正确性,不可用。 参考对齐 C++ downcast 路径 → bit-exact,C++ 一行不改(“我更精”保住,School B 改 oracle 不改实现)。
  • 小样本容差是假象(我臆断 0.1 被 2000 seed 打脸):容差必须扫够样本找重尾,小样本的”最大值”不是真上界。印证用户立的规矩:不确定要测,不能臆断。
  • f32 独立 oracle / bf16 契约对齐 oracle 的分工原则:哪边 torch 默认和 C++ 契约发散,哪边才需要对齐。reduce/累加恒 f32 的 op(rmsnorm/rope/matmul,torch 默认也对齐)用独立 oracle + allclose;非线性 op 的 f32 中间域(sigmoid/softmax/silu,torch 默认 per-step downcast 发散)用契约对齐 oracle + bit-exact。整个项目 bf16 测试哲学统一在这一条。

  • bf16 契约分歧 + f32 兜底分工(School B 集成 op 延伸):bf16 下 C++ “我更精”vs PyTorch 每步 downcast,round 噪声经 down_proj cancellation 放大,与装配 bug 差异同量级(正常 ~2.4e-4,ln2 错张量 ~4.9e-4,窗口窄且重叠)→ 无法靠容差分离。f32 无 downcast 分歧:正常 ~1e-8 vs bug >1e-4,窗口 4 量级。结论:集成 op 装配 bug 由 f32 case 兜底(bit-exact 级),bf16 case 诚实定位”路径不回归”(只验 bf16 路径跑通/dtype/bridge 无 crash,不试图抓装配 bug)。硬要 bf16 容差抓 bug = 0.1 坑重演。
  • ablation 是测容差有效性的唯一方法:case 绿不够——注入 ln2 错张量(rmsnorm(attention_x,...)→rmsnorm(x,...)),case 必须变红才证明 load-bearing(正确✓/注入✗/还原✓)。case2 atol=1e-2 看似绿,ablation 暴露它注入 bug 仍绿 = 容差太松、抓不住装配 bug → 才有”路径不回归”的诚实定位。绿测试不一定是有效测试,只有”改坏代码它就红”的测试才真挡 bug。容差松紧不能靠”过了”判断,必须 ablation 量”正常噪声 vs bug 差异”的窗口。

mmap 全量

  • 权重从不进 RAM:mmap 映射整个 safetensors,header 是 length-prefixed JSON(前 8 字节 uint64 LE),parse 出每个 tensor 的 offset/shape/dtype,C++ Tensor 直接是指向映射页的 non-owning view。5GB 模型 0 内存拷贝、启动即用、按需 page-in。make_weight_view 算 addr + 8 + header_len + data_start_off + *data_start_off 拿到 tensor 起点。
  • RAII + fd 不存成员:MMapFile 析构 munmap;fd 在 mmap 成功后立刻 close(mapping 自带文件引用,POSIX 下 mapping 比 fd 活得久,munmap 不需要 fd)。不存 fd 成员 = 避免一个可能被 double-close 的 stale fd。构造失败要手算补偿:构造体抛异常不触发析构(只析构成员/基类,标量无析构),所以 mmap 失败后的 munmap 要在 throw 前手动做,否则泄漏。
  • view ctor 不查对齐,真守卫在 make_weight_view:ptr = mmap_base + offset 的对齐取决于 offset 不是 mmap base(mmap base 4KiB 页对齐,base+offset 未必对 dtype 对齐)。view ctor 信任 caller;make_weight_view 查 offset % dtype_size == 0。
  • offset 越界用安全减法防溢出:bounds check view_end <= mmap_end 不能直接 start + size <= end——start + size 可能 int64 溢出绕回小数,假通过。先 if (size > end - start) throw 再用差,避免加法溢出。这是防御校验族「check 要在它保护的运算之前」的一员。
  • bf16 跨语言 bridge 走 uint16 重解释,不是 f16:bf16 ≠ f16(不同格式)。唯一 bit-exact 的跨界是 t.view(torch.uint16).numpy()(把 16 个 bf16 bit 当 uint16)→ C++ from_numpy_raw(..., BFloat16) 重解释回去;反向 to_numpy_raw .view(uint16) .view(torch.bfloat16)。这条 round-trip 是所有 parity 判断的命门——它位级错了,上层所有 allclose 都在测 bridge 误差不是 C++ 正确性。f32 直接拷。
  • cpp_to_torch 的 ref_shape 是信任陷阱:xstar Tensor 出来是 flat uint8 buffer(to_numpy_raw),没形状,ref_shape 外部传。reshape 到 ref_shape 若 C++ 真实 shape 的元素数相同但维度不同,静默成功、掩盖 shape bug。正解:调用前 assert cpp.shape() == ref.shape(test_cpp_qwen2_model.py 有这个 pattern),bridge 不替你兜。
  • 绿的保护伞:bridge 只测「形状匹配」→ 造「元素数同但维度不同」(应被 assert 挡);mmap 只测小文件 → 造「空文件」「header 长度 > 文件大小」「data_offsets 跨度 ≠ nbytes」。

端到端

  • 两层验收:单层强 judge + 端到端弱验收:单层 per-layer allclose(TOLERANCES 表:embedding equal / rmsnorm 1e-6 / rope 1e-2 / attention 2e-2 / mlp 5e-3 / block 0.2 放大)——证明每个 op port 忠实;端到端走 greedy 20 步 + 流畅生成 + argmax 一致,不是 allclose。
  • 端到端不能 allclose,为什么:24 层 bf16 累加顺序差异让 logits 偏 ~0.578125,但 argmax 稳、文本流畅。强行 allclose 会把「bf16 跨 24 层的累加序漂移」(无害)判成「port 错」(假红)。强 allclose 留给单层,端到端只看生成质量——这是「对拍分层强弱点设计」。
  • max_diff 恒定不随 seq_len 涨 = 误差来自单步 matmul 不是层间累积:观察 max_diff 在 20 步里恒定(seq_len 从 5 涨到 25,diff 不动)→ 误差是每步 lm_head matmul 的 bf16 累加序差异(每步重算),不是 24 层 hidden 的累积。一个验收 harness 不只能验货,还能反向定位误差源。
  • 参考必须跑 CPU:C++ 是 cpu-only。若 ref 跑 cuda,你把「CUDA bf16 vs CPU bf16」和「C++ port vs xstar-Py port」两个误差源混在一起,污染判断。实验里只有一个变量的纪律搬到工程对拍——device 对齐是底线。
  • model/lm 不进 judge 表:judge 的 TOLERANCES.get(layer) 对 model/lm 返回 (None,None) → 抛 ValueError。这是设计不是疏漏:整模型/端到端走 coherence(流畅 + argmax),不走 allclose。强 judge + 弱 end-to-end,各管各的。
  • NaN 根因是未初始化 bias,不是 einsum 不是 RMSNorm:Linear 默认 bias=True → torch.empty 未初始化 bias;Qwen2ForCausalLM 构造 lm_head 没传 bias=False(HF 的 lm_head 无 bias);loader 不复制这个不存在的 key → 残留内存含 nan/inf → 加到干净 matmul 上 → NaN logits。触发是非确定性的(torch.empty 残留跨 run 变),所以 parity_qwen2(cuda)曾「碰巧过」,修了之后「必然过」——输出不变是 expected。教训:未初始化内存 bug 是非确定的,「它过了」不等于「它对」。
  • 绿的保护伞:端到端只测「生成流畅」→ 注入 lm_head 未初始化 bias(应让流畅度崩 / argmax 全错);单层只测「allclose 过」→ 注入 ln2 喂错张量(应让 block allclose 红,证明容差 load-bearing,见 ablation)。
